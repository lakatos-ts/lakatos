# CLAUDE.md

`@lakatos/lemma`: the Lemma annotation language and its reference implementation. Charter: no runtime code (that is pabst's), no in-repo dependency; it owns the `typescript` dependency, the typecheck gate, and the parser bridge (`src/estree.ts`, `src/strip-types.ts`) because every consumer needs them. The `lemma` bin (`src/cli.ts`) prints a checked-program document per file (`src/document.ts`); `schemas/lemma-document.schema.json` pins it and `schemas/tarski-estree.schema.json` the ESTree inside it, which the Lean decoder in `thales/Tarski/` is written to. The one piece of engine code here is thales's emitter (`src/emission.ts`, `emission-ast.ts`, `readings.ts`, `module-graph.ts`): document v1 carries its output as `emission` beside each annotation's outcome, pinned by `schemas/thales-emission.schema.json`, until the engine-neutral document moves that lowering into Lean (`docs/design/repo-split.md`). Its invariants are thales's contract with it and are listed in `thales/CLAUDE.md`; thales's own fixtures and corpus pin its output from `thales/tests/emission-corpus.test.ts`. A change to either schema is a change to the seam: bump `SCHEMA_VERSION` when a reader of an older document would misread a newer one. `tests/fixtures/` holds the bridge's goldens, of which thales keeps copies that nothing checks against these; `tests/fixtures/emission/` holds the copies of thales fixtures the emitter's unit tests read.

`src/index.ts` is the only export (`"."` in `package.json`); a name reaches an engine or the CLI by being added there, and `exports` refuses any other route in. `spec/` is the language: change `grammar.ebnf` and `semantics.md` with the parser, and add a fixture under `spec/fixtures/` for every accepted or rejected form (membership is the expectation; `spec/fixtures/README.md` explains the four corpora). `tests/` may reach lemma internals but import nothing outside `lemma/`; `tests/package.test.ts` pins the published package's shape; `tests/helpers/` holds what they share.

Build, typecheck, test, and format from the repo root. This package is a composite `tsc` project the root references, so `npm run build` at the root emits `dist/` here before the engines resolve it; vitest runs it from source through the alias in the root `vitest.config.ts`. A clean rebuild is `rm -rf dist lemma/dist`.
